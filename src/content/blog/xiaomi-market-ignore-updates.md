我遇到过一个很具体的小需求：某个系统应用商店不断提示某些应用更新，但 UI 里没有我想要的“忽略这个版本”入口。

与其不停点关闭，我开始看它在本地到底怎么记录更新状态。

## UI 是数据库状态的一种投影

很多 Android 应用会把“是否忽略”“上次检查时间”“目标版本”等状态保存在 SQLite 数据库里。拿到足够权限后，观察数据库结构，可以帮助理解 UI 背后的状态机。

真正值得注意的不是“改哪一行 SQL”，而是先确认：

- 哪张表负责更新记录；
- package name 和版本号如何关联；
- 忽略状态是永久还是针对某一版本；
- 应用启动后会不会从服务端重新覆盖本地值。

## 修改之前先备份

直接改系统应用数据库风险不小。最基本的保护是先备份文件，并确认数据库没有被进程持有导致 WAL 状态不一致。

这类小排障给我的启发是：**当 UI 缺少一个开关时，理解它的数据模型往往比寻找隐藏按钮更有价值。**
